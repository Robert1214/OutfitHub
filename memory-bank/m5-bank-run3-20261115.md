## 2. 新问题：P03-T2 有预算+场合却仍要求澄清

P03-T2 是「通勤穿的，预算 400 以内」第二轮。工具返回了 `needs_clarification`。

查服务端日志，工具**入参是对的**：`other:["通勤"]`、`budget:[40000,"item"]`，但返回 `status: needs_clarification, clarification: ["上衣具体款式或风格"]`。

用同样入参直接调工具复现不了（返回 matched）。**原因**：写入 `narrowing` 判断时漏了「无法核实的偏好条件」这一项——「通勤」被识别为场合后从 `otherRequirements` 移除，某些路径下四项 narrowing 全为假，于是误判为「顾客什么都没说」。

**修复**：把 `unresolved.length > 0`（有未能核实的偏好条件）也算作已给方向，不再追问。

验证（工具直连）：

| 输入 | 结果 |
| --- | --- |
| 只有品类 | ✅ 先问款式 |
| 品类 + 预算 | ✅ 正常推荐 |
| 品类 + 预算 + 通勤 | ✅ 正常推荐（修复前为澄清） |

> 注：本轮运行的日志证据显示接口层确实返回了澄清；修复后已重新验证。**下次重建基线时要重跑确认。**
