### P2 结论（已补测，确认为工具缺口）
预算 400 元、口径「只买下装」时，工具仍返回整套方案并按 818 元合计描述。**原因**：`src/lib/assistant-outfits.ts:121` 虽在 checkedConstraints 记录了"仅新购买下装的预算"，但 `assessedPriceCents` 只区分是否计上衣（false → 359），没有任何字段告诉回答节点"本次只应在正文里报 359、不报 818"。回答节点因此照抄 outfitTotalCents。
影响：顾客说"预算 400 只配裤子"，可能被告知"818 元"。当前 400 ≥ 359，未触发超预算拦截，属于漏网；若限制为 300 元则会被判超预算 59 元。
修复方向（需用户同意后改代码）：下装单件口径时，在返回体增加 `reportedPriceCents` 或让 products/outfits 只携带下装金额；并同步回答规则。**未改代码**。

### D1（已定位，非 Dify 故障）· 续轮报「暂时不可用」的真实原因

**最初判断错误**：一度认为 Dify 服务端返回 400。重启 api、重建 redis/nginx 后现象依旧；逐项隔离后确认是**我方代码问题**，Dify 本身正常（首轮、续轮、中英文、streaming/blocking 均为 200）。

隔离过程：
1. Windows curl 直连 Dify：首轮 200，之后连续 400 → 初判 Dify 异常。
2. 同样的 body 换成 node `fetch`：全部 200 → 400 是 curl + 中文长 body 的本机组合问题，非 Dify。
3. node fetch 传递**不存在**的 conversationId → 干净的 404 `Conversation Not Exists`。
4. 回到 `/api/chat` 复测续轮：仍失败，`assistant_logs.error = dify_404`。
5. **根因**：`src/app/api/chat/route.ts:229-231` 用 `anon:${anonId ?? randomUUID()}` 生成 Dify `user`。测试脚本每轮换新 anonId → 第 2 轮带旧 conversationId + 新 user → Dify 判定会话不属于该 user → 404。
6. 固定 anonId 重测三轮：全部 200，续轮正常承接。

→ 真实浏览器会持久化 anonId，**正常使用不受影响**；但任何测试/调用都必须固定 anonId。
