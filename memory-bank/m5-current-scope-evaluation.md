每轮分别记录：

| 维度 | 通过标准 | 证据 |
| --- | --- | --- |
| 条件理解 | 明确预算/品类/风格/主体/否定条件未错漏，多轮只更新被改的条件 | 同轮requirements；缺中间输出时标未核实，不能仅由末端猜测 |
| 约束与金额 | 核对真实商品，预算包含关系/总价正确，不拿鞋或裙替代裤子 | 同轮HTTP与固定商品快照 |
| 合理行为 | 需要时只澄清一个必要问题；明确时不反复确认；未匹配不擅自放宽条件 | 用户消息、工具状态、最终回复 |
| 事实与来源 | 不编造商品、价格、库存、合身、退换或正在浏览的来源 | 回复逐项与工具/页面资料对照 |
| 交付一致 | 商品标记仅本轮允许候选，超预算/无匹配不输出；卡片数据一致 | 原始标记、ID查卡结果；视觉单独记录 |
| 技术完成 | 无请求/解析/流错误，不将空回答当成功 | HTTP/stream事件、错误、时间戳 |

结果使用通过/失败/未核实/不适用四态。未核实项不默认为通过，不把“错误被正确解释”当作推荐任务已完成。

## 4. 指标分母

- **可完成任务成功率**：标记completionEligible=true的会话，最终交付符合需求的推荐且各轮无硬约束违规的数量/该组全部已运行会话。按完整会话算；中间正确协商预算不算最终完成，最终修复也不能抹掉前轮违规。
- **边界处理正确率**：其他会话中，正确澄清/明确未核实/解释无匹配的数量/该组全部已运行会话，单独报告。
- **硬约束违反**：预算、品类、库存、未经同意改条件等，报告次数、涉及会话数和分母；不与轻微措辞混为同级。
- **应答事实与多余澄清**：逐轮人工审核，保留错误句子及依据。没有事实陈述的澄清轮不计入商品事实正确率分母。
- **有解却未推荐**：在已标注当前数据中有合法候选的轮次，检查是否被错误挡住；无已知答案集合的泛化审美不报告召回率。
- **耗时与成本**：逐轮首段/总耗时，完整任务总耗时和调用/重试数；可取得的usage与费用完整记录。拿不到的标未知，不能记0；样本少时展示原值，不夸大P95结论。

不给“整体准确率”一个混合数字掩盖这些区别。31项代码回归和历史49行结果独立列出，不并入本次模型评估分母。

## 5. 执行方式与修复规则

每个会话新建身份/会话，组内保留真实历史和页面上下文；逐轮保留输出，不能像旧脚本那样合并多轮商品ID后当作每轮都正确。每次运行使用新目录，记录caseSet/code/data/DSL哈希。首次失败保留；重试、修复后重跑单独存档。

旧scripts/eval-assistant.mjs会覆盖旧结果文件、合并多轮回答/ID且只覆盖少量行为，不能未经调整直接当本轮评分器。后续准备独立执行器或独立结果文件，先验证当前发布配置一致再运行。若执行渠道拿不到中间字段，端到端结果与分层判分分开，不伪造工具状态。

第一轮先跑全份准备好的用例；报错也保留并计技术失败。以本轮未修改配置重复少量关键/保留题观察波动，重复次数和费用预算在执行前确定。若修改Prompt，先做受影响回归，最终再以同一版完整复验；不能拼接不同版本各自的最好结果。

发布门槛的数值仍待用户结合基线和业务代价决定。此处仅沿用已有硬规则，不替用户宣布“通过率多少就上线”。首轮报告完成后才讨论模型对照、性能优化或用户任务观察的具体优先级。
