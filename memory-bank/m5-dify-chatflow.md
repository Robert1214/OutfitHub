# M5 Dify Chatflow 搭建稿 v0

> 目标：从当前“最小测试流”升级为可评测的导购 baseline。
> 当前问题：HTTP 节点对所有请求都调用、没有把工具结果交给回答 LLM，回答是通用聊天，且带 `<think>`。
> 原则：先做最小商品分支，跑通后再加政策/尺码/转人工。

## 1. 目标结构

用 **Question Classifier（问题分类器）** 时，它自带多个分类出口，**不需要再加 IF/ELSE**：

```text
Start
  → 问题分类器
      ├─ 出口「商品推荐」→ 参数提取 LLM → HTTP 商品查询 → 回答 LLM → Answer
      ├─ 出口「政策咨询」→ 知识库检索 → 回答 LLM → Answer
      ├─ 出口「尺码建议」→ 尺码工具 → 回答 LLM → Answer
      └─ 出口「其他」  → 回答 LLM → Answer
```

只有当你改用「一个 LLM 输出 intent JSON」时，才需要在它后面加 IF/ELSE 条件分支：

```text
Start → 意图识别 LLM → IF/ELSE（按 intent 分流）→ ...
```

v0 先用问题分类器，**保留四个类别**。商品推荐走完整链路；其余三个出口先接占位 Answer，保证能发布，后续再替换成知识库/尺码/转人工。不要为了简化而临时改成两类。

## 2. 节点配置

### Start

- 使用系统变量 `{{#sys.query#}}` 作为用户输入。
- 增加一个**可选**文本输入字段 `product_context`（见第 7 节）；不填不影响普通问答。

### 意图分类

用 Dify 的 **Question Classifier** 节点，先不要用 Agent。

分类：

- `商品推荐`
- `政策咨询`
- `尺码建议`
- `订单售后`
- `转人工`

分类节点输出变量通常为 `class_name`。

**重要**：问题分类器每个分类都有一个独立出口。直接把「商品推荐」出口连到下一节点，不需要再接 IF/ELSE。  
如果你看到的是单个出口，再在它后面加 IF/ELSE，按 `class_name` 判断。

### 商品/搭配分支

#### A. 参数提取 LLM

Prompt：

```text
你是服装店导购的检索参数提取器。根据用户问题提取商品查询参数。
只输出 JSON，不要解释，不要 Markdown。

字段：
- q: 关键词，字符串，没有就空字符串
- category: tops/bottoms/dresses/outerwear/accessories/shoes 之一，无法判断为空
- styleTags: 风格标签数组，如 ["中性","复古","通勤"]
- occasionTags: 场合标签数组，如 ["通勤","约会","婚礼宾客"]
- minPriceCents: 最低预算，整数分，没有为 null
- maxPriceCents: 最高预算，整数分，没有为 null

用户问题：
{{#sys.query#}}
```

如果 Dify 版本支持结构化输出，直接声明 JSON schema；如果不支持，用 Code 节点解析。

#### B. HTTP Request 节点

- Method：`GET`
- URL：`http://host.docker.internal:3000/api/assistant/products`
- Header：
  - `x-assistant-token` = 项目 `.env.local` 的 `ASSISTANT_TOOL_TOKEN`
- Query Params：
  - `q` = 参数提取结果中的 `q`
  - `category` = `category`
  - `styleTags` = 数组转逗号字符串
  - `occasionTags` = 数组转逗号字符串
  - `minPriceCents` / `maxPriceCents`
  - `limit` = `5`
- 输出变量名：`body`
- 响应格式：JSON

不要像现在这样把 `q` 写死成「通勤」。

#### C. 回答 LLM

Prompt：

```text
你是 Wardrobe 的导购助手。请只根据下面的商品工具结果回答。

规则：
1. 只能推荐工具结果中的商品，不得编造商品、价格、库存、折扣。
2. 商品推荐最多 4 件。
3. 在回答末尾输出商品 ID 标记：
   [[PRODUCTS:id1,id2]]
4. 如果没有匹配结果，直接说明没有找到，并给一个筛选建议。
5. 不承诺真实支付、发货、鉴定；涉及鉴定时带「演示设定，不构成真实承诺」。
6. 不输出内部推理过程，不要出现 <think> 标签。
7. 退换按商品 returnPolicy：RETURNABLE=支持退换（演示），NO_RETURN=不支持退换（演示）。

用户问题：
{{#sys.query#}}

商品工具结果：
{{#body#}}
```

#### D. Answer 节点

- 引用回答 LLM 的输出变量。
- 商品卡片标记 `[[PRODUCTS:...]]` 保留在回答里，前端负责解析。

## 3. 政策分支（第二阶段）

知识库文档已起草：`memory-bank/m5-knowledge/`（发货、退换、正品、演示支付、尺码、FAQ）。

知识库参数（当前决定：2026-11-03）：

- 分段：自动分段；最大 500 tokens，重叠 50；分隔符 `\n\n`。
- 索引：**先用「经济 / 关键词」**（本机内存紧张，暂不装 Ollama embedding）。
- 检索：全文 / 关键词检索；topK 3；score 阈值 0.5。
- 待办：内存充足或接入托管 embedding 后，切换「高质量索引 + 混合检索（向量 0.7 / 关键词 0.3，rerank 可选）」并重新索引。

Dify 操作：

1. 打开 Dify「知识库」→ 创建 `Wardrobe 店铺政策`。
2. 上传 `memory-bank/m5-knowledge/` 下的 6 个 Markdown 文件，等待索引完成。
3. 回到 Chatflow，把政策咨询出口的占位 Answer 删掉，改成：
   `知识库检索 → 回答 LLM → Answer`。
4. 知识库检索设置（当前经济索引）：
   - query：`{{#sys.query#}}`
   - 检索模式：全文 / 关键词
   - topK：3
   - score 阈值：0.5
   - 混合检索 / embedding：待办，等内存或托管 API 方案确定后再开
5. 回答 LLM：
   - 在 LLM 节点的「上下文 / 设置变量值」里选择 `知识库检索.result`
   - Prompt 里用 Dify 的上下文变量 `{{#context#}}`，不要直接写 `result`。`result` 是 chunk 数组，`content` 是每个 chunk 的字段，不能直接当完整文本用。

```text
你是 Wardrobe 的导购助手。只根据下面的知识库检索结果回答。
不要编造政策、时间、赔偿或鉴定服务。
如果检索结果为空，回答「当前没有找到明确政策，建议查看商品详情页或转人工」。
回答要简洁，不要输出 <think>。

用户问题：
{{#sys.query#}}

知识库检索结果：
{{#context#}}
```

6. 测试：
   - 「可以退换吗？」→ 应说明按具体商品不同，并问是哪一件；不能回答占位文案。
   - 「多久发货？」→ 应回答 48 小时内（演示），不承诺当天发货。
   - 「支持鉴定吗？」→ 必须带「演示设定，不构成真实承诺」。

知识库只放政策/FAQ/尺码指南，不放商品。商品事实仍走 HTTP 商品工具。

## 4. 尺码分支（第二阶段）

v1 先用引导式 Answer，不假装已经算出结果：

> 请告诉我是哪件商品，以及你的身高/胸围（上装）或腰围/臀围（下装）；也可以在商品详情页填写身材信息，查看「尺码建议」。

后续再接 `size-engine` 工具，规则：

- 不要交给 LLM 猜。
- 上装：身高 + 胸围 + 成衣胸围 + 版型
- 下装：腰围 + 臀围 + 成衣腰围 + 臀围 + 版型
- 缺数据时引导填写，不输出 S/M/L。

## 5. 转人工分支

v1 先用固定 Answer：

> 已记录转人工请求；演示环境不会真的联系客服。你可以先查看商品详情页，或稍后再试。

后续再写入 handoff 记录。

## 6. 关键排错

- **401**：`x-assistant-token` 不对；必须用 48 位本地 token，不是 Dify `app-...` Key。
- **403**：Dify SSRF 代理未放行 `host.docker.internal`；见 `m5-dify-setup.md`。
- **404**：路径不是 `/api/assistant/products`。
- **500**：先看 Next dev server 是否正常。
- **回答带 `<think>`**：改用 `deepseek-chat`，或在 `/api/chat` 代理层剥离；不要展示内部推理。
- **HTTP 节点 400**：Dify 的推理模型可能把 `<think>...</think>` 连同关键词写进 `q`，超过长度限制。优先在 LLM 节点打开「启用推理标签分离」；商品 API 已做兜底清洗，会剥离 think 标签并截取尾部关键词。
- **所有问题都查商品**：HTTP 节点没有放在商品分支里，或意图分类没有接 IF/ELSE。

## 7. 商品上下文（商品页「问导购」）

> 详细设计理由、Prompt 逐条解释和故障排查见 `m5-context-prompt-detail.md`。

商品页的「问导购」会打开 `/assistant?product=<slug>`。Next 的 `/api/chat` 查询该商品，并随 Dify 请求发送：

```json
{
  "product_id": "...",
  "product_name": "米白针织开衫",
  "product_slug": "ivory-knit-cardigan",
  "product_context": "{\"id\":\"...\",\"name\":\"米白针织开衫\",\"material\":\"...\",...}"
}
```

Dify 侧只需做一个最小配置：

1. **Start 节点** → 右侧面板「输入字段」→ 点右侧 `+`：
   - 变量名称：`product_context`
   - 显示名称：`当前商品资料`
   - 字段类型：`段落`（不要选「文本」；文本最多 256 字符，商品 JSON 会超）
   - 最大长度：`4000`（如果有这一项）
   - 必填：关闭（选「可选」）
2. **商品分支的回答 LLM** → 在 Prompt 最前面加入：
   - 在 Prompt 输入框里输入 `{`，选择 Start → `product_context`（不要手打变量路径）：

```text
当前商品资料（用户问“这件/这款/它”时优先使用；为空则忽略）：
{{#start.product_context#}}
```

3. 把回答 LLM 原有的「只根据商品工具结果回答」改成「同时根据当前商品资料和商品工具结果回答」，并补充规则：

```text
你是 Wardrobe 的导购助手。请根据“当前商品资料”和下面的商品工具结果回答。

规则：
- 用户问当前商品本身（材质、价格、颜色、尺码数据、退换政策）时，只根据“当前商品资料”回答。
- 用户问搭配/推荐时，才使用商品工具结果；可以把当前商品作为搭配主体，但不要把工具结果里的其他商品说成当前商品。
- 当前商品资料为空时，不要假装知道用户在看哪件商品。
```

4. 保存并**发布**应用。不需要在 Dify 里手动输入商品信息；`product_context` 由 Next 每次请求自动传入。

验收：

- 打开 `/assistant?product=ivory-knit-cardigan`，页面显示「正在咨询：米白针织开衫」。
- 问「这件是什么材质？」→ 回答必须是米白针织开衫的材质，不能变成其他商品。
- 问「这件可以退换吗？」→ 按该商品的 `returnPolicy` 回答。
- 问「通勤上班穿什么？」→ 仍能返回商品卡片。

## 8. P0 修复（2026-11-04）

当前评测暴露两个高优先级问题：A13 意图误判，A31/A32 政策分支不读商品上下文。

### 8.1 A13：小个子短款上装被分到尺码建议

问题不在用户表达，而在问题分类器没有边界说明。当前四个分类只有名称，`instruction` 为空。

在问题分类器 →「高级设置」→ 指令中填入：

```text
你是服装店导购的意图分类器。按以下边界分类，只输出分类，不要解释。

- 商品分类：用户想找、浏览、筛选或推荐商品，即使提到身高、体型、肤色、场合，也归商品分类。例如“小个子适合的短款上装”“推荐一双通勤鞋”“有裙子吗”。
- 尺码建议：用户已经指向某件具体商品，询问尺码数据、是否合身、会不会紧/松。例如“这个码我穿会紧吗”“这件胸围多少”。
- 政策咨询：退换、发货、正品、支付、护理等店铺政策。
- 转人工：投诉、要求人工、连续无法解决。
```

关键边界：**提到身高/体型但在找商品 → 商品分类；已经指向具体商品问合不合身 → 尺码建议。**

### 8.2 A31/A32：政策分支不读当前商品

政策分支的「回答 LLM」现在只接知识库，不知道用户在看哪件商品。把它的 System Prompt 改成：

```text
你是 Wardrobe 的导购助手。请根据“当前商品资料”和下面的知识库检索结果回答。

当前商品资料（用户问“这件/这款/它”时优先使用；为空则忽略）：
{{#start.product_context#}}

规则：
- 如果当前商品资料不为空，用户问这件商品是否可退/换，按资料中的 returnPolicy 回答：
  - RETURNABLE = 支持退换（演示）
  - NO_RETURN = 不支持退换（演示）
  不要用通用知识库规则覆盖商品级 returnPolicy。
- 如果当前商品资料为空，回答“退换规则按具体商品不同，请告诉我是哪一件”，不要给统一答案。
- 其他政策问题只根据知识库检索结果回答；不要编造政策、时间、赔偿或鉴定服务。
- 回答末尾输出 [[PRODUCTS:商品ID]]，ID 只能来自当前商品资料；没有有效 ID 就不输出。
- 回答简洁，不要输出 <think>。
```

`{{#start.product_context#}}` 用变量选择器插入：在 Prompt 输入框输入 `{`，选 Start → `product_context`。

政策分支的 Answer 节点继续引用这个 LLM 的输出，不需要改。

### 8.3 验收

- A13「小个子适合的短款上装」→ 走商品分类，返回针织开衫/针织背心
- G02「这个码我穿会紧吗」→ 仍走尺码建议
- A31「这件可以退吗」（米白针织开衫）→ 支持退换（演示），输出当前商品 ID

## 9. P1 尺码分支（2026-11-04）

尺码判断不交给 LLM。Next 的 `/api/chat` 用 `size-engine` 计算好结果，通过 `size_advice` 传给 Dify；Dify 只负责展示。

### 9.1 Start 增加输入

Start 节点 → 输入字段 → `+`：

| 配置项 | 值 |
| --- | --- |
| 变量名称 | `size_advice` |
| 显示名称 | `尺码建议` |
| 字段类型 | 段落 |
| 最大长度 | `4000` |
| 必填 | 关闭 |

### 9.2 替换尺码分支占位回答

把「尺码建议」出口连接的占位 Answer（当前内容是“请告诉我是哪件商品……”）改成：

```text
{{#start.size_advice#}}
```

说明：

- `size_advice` 由 Next 传入，包含商品名、合身/偏紧/偏松、放量数据、调整方向和当前商品 ID 标记。
- 商品标记已经包含在 `size_advice` 文本里，Answer 节点不要重复输出 `[[PRODUCTS:...]]`。
- 没有商品上下文时，`size_advice` 是引导话术，不含商品标记。
- 不输出 S/M/L；这是 `size-engine` 的硬规则。

### 9.3 验收

- G02「这个码我穿会紧吗」（米白针织开衫，165/88/68/92）→ 合身，输出当前商品 ID
- A02「这条裤子我穿会紧吗」（黑色阔腿裤，165/88/68/92）→ 偏紧，输出当前商品 ID
- 无身材数据 → 引导补充，不猜尺码

## 10. P2 搭配 / 相似款 / 肤色选色（2026-11-04）

P2 不新增 Dify 分支，商品工具根据 `q` 和当前商品 ID 自动切换检索模式：

- `q` 含「搭配 / 配什么 / 怎么穿 / 一套」→ 搭配推荐
- `q` 含「相似 / 同款 / 类似」→ 相似款
- `q` 含「显白 / 显黑 / 肤色 / 黑黄 / 颜色」且无上下文 → 肤色友好选色

### 10.1 Start 增加商品 ID

Start 节点 → 输入字段 → `+`：

| 配置项 | 值 |
| --- | --- |
| 变量名称 | `product_id` |
| 显示名称 | `商品 ID` |
| 字段类型 | 文本 |
| 最大长度 | 默认即可 |
| 必填 | 关闭 |

`product_id` 由 Next 自动传入，不要把它和 `product_context` 混用：`product_context` 是完整商品 JSON，`product_id` 才是单个 ID。

### 10.2 HTTP Request 节点

把商品 HTTP 节点的 Query Params 改成：

```text
q:{{#1793705786188.text#}}
contextProductId:{{#start.product_id#}}
limit:5
```

`contextProductId` 用变量选择器插入 Start → `product_id`，不要手打，也不要选 `product_context`。

### 10.3 回答 LLM 规则补充

在商品分支回答 LLM 的规则中加：

```text
- 推荐搭配或相似款时，排除当前商品本身；如果工具结果里出现当前商品，不要再次推荐。
- 搭配推荐优先覆盖下装、鞋、包/配饰，最多推荐 4 件。
- 肤色/颜色建议类问题：只输出符合肤色规则的推荐商品 ID；避雷色商品不要主动推荐，也不要输出商品 ID。
```

### 10.4 肤色咨询

肤色冷暖判断、配色规则、`skin.jpg` / `color.jpg` 参考图和完整 Prompt 见：

```text
memory-bank/m5-color-guide.md
```

这条规则放在商品分支回答 LLM，不要放知识库；G05 走商品分支，不会触发政策知识库检索。

### 10.5 验收

- G04「我看中了这件，有什么搭配推荐吗？」→ 以米白针织开衫为锚点，返回黑色阔腿裤、帆布托特包、白色板鞋等搭配
- G05「黑黄皮肤，有什么不显黑的颜色或款式？」→ 返回米白开衫、灰色背心、驼色大衣、牛仔裙等，不做肤色歧视/医疗判断
- G07「有没有和这件相似的款？」→ 返回灰色针织背心、黑色真丝衬衫等相似商品，不返回当前商品本身
