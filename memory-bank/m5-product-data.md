建议数据模型新增：

```prisma
enum ReturnPolicy {
  RETURNABLE
  NO_RETURN
}

// Product
returnPolicy  ReturnPolicy @default(RETURNABLE)
styleTags     String[]     @default([])
occasionTags  String[]     @default([])
```

`tags` 继续保留为搜索关键词；风格/场合使用独立字段，避免“针织”“通勤”“连衣裙”混在一个数组里。

## 3. 当前数据的问题

1. **`tags` 语义混杂**：`针织` 是材质/工艺，`通勤` 是场合，`连衣裙` 是品类，`温柔` 是风格。用同一数组做筛选，意图识别和工具参数都会变模糊。
2. **没有 `returnPolicy`**：当前商品页统一写「不退换」，与 M5 的“按商品”决策冲突。
3. **没有风格/场合字段**：问“中性风”“婚礼”“通勤”时，只能靠 LLM 从描述里猜，稳定性差。
4. **描述偏短**：可以补“适合谁、什么场景、怎么搭”，让助手有依据解释，而不是编。
5. **没有受众字段**：问“男生可以穿吗”时，先用 `styleTags=中性` + 描述回答，不急着加性别字段。

## 4. 我建议的补全顺序

1. **先加 `returnPolicy`**，按上表给 13 件商品赋值。
2. **加 `styleTags` / `occasionTags`**，把“风格/场合”从 `tags` 里拆出来；原 `tags` 保留搜索用。
3. **补 13 条描述**：每条增加一句“适合场景 + 搭配建议”，但不要写成营销长文。
4. **M5 不换图**；M4 试穿或最终录屏前，再换 4~6 张有授权的真实感图片。
5. 商品图仍然用占位图时，页面和演示话术继续保留「演示占位图 / 演示环境」标识。

## 5. 这对 M5 的直接收益

- 商品工具能按 `occasionTags` / `styleTags` 精确过滤，而不是靠 LLM 猜。
- “通勤”“婚礼”“中性风”“相似款”这些评测问题有稳定的数据结构支撑。
- 退换问答可按商品回答，不会出现统一口径冲突。
- 面试时可以讲清楚：**AI 效果的上限，首先取决于商品数据质量，而不是模型或 Prompt。**
