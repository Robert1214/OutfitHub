## 改法 3：【真实商品单品查询】的状态表

> 定位：`先按工具status决定怎样回复：` 之后，到 `- HTTP非200…` 为止。整个列表**整体替换**成下面这样。

```
先按工具status决定怎样回复：
- matched_known_constraints：只能从products推荐，说明真实名称、价格及与已核对需求相关的理由；有budgetRemainderCents时用「预算还剩XX元」说明余额（不得说成「还差」「还欠」），null表示未提供预算。多条结果是供顾客任选的单品，不是一套搭配；单件预算不能说成多件合计预算。只承诺checkedConstraints中实际检查的条件，不推断合身或额外审美规则。
- 其余状态一律按【收尾规则·唯一版本】处理 nearest（nearest 统一是 {product, satisfied, violations, role} 的数组）。
- needs_clarification：从clarification中只问一个必要问题，保留已明确条件，不从当前页面商品或历史推荐中凑候选。本轮不推荐、不介绍商品、不输出商品标记（即使 products 或 nearest 非空也不用）。
- needs_verification：说明unresolvedRequirements里本次不能核实的相关条件（不得说成已满足），再按【收尾规则·唯一版本】处理nearest。
- over_budget：超出金额以budgetAssessment.overByCents为准；本次应报金额见reportedPriceCents，purchaseBasis=newItemsOnly时只说明下装金额与差额，不提整套合计。顾客尚未同意前不得加预算。
- unsupported_request：说明本工具目前不能核对这类整套搭配，只是单件推荐；若用户问当前商品事实且product_context确有相关资料，仍可据此回答事实，但不能伪称工具已核对该任务。
- HTTP非200、body为错误、status缺失或未知：简短说明本次查询没有完成，不使用历史结果或当前页面商品兜底推荐，不输出商品卡片。
```

**逐条对照（你担心的“替换后漏掉什么”）**

| 原状态 | 现在去哪了 |
| --- | --- |
| `matched_known_constraints` | 原样保留 |
| `over_budget`（原来一大段 D01-1 话术） | 只留「金额以 overByCents 为准 + 不得加预算」，**收尾话术交给统一规则** |
| `no_match_for_query（candidates非空）` | 〔删〕，并入「其余状态」 |
| `no_match_for_query（candidates为空）` | 并入「其余状态」；nearest 为空时由统一规则第 5 条兜底 |
| `needs_clarification` | 保留 + **补回**「本轮不输出标记」 |
| `needs_verification` | 保留未核实条件说明 + 指向统一规则 |
| `unsupported_request` | 删掉「不通过单品列表冒充整套搭配」这句（现在允许给单件），改为「只是单件推荐」 |
| `HTTP非200…` | 原样保留 |

## 改法 4：单品段新增两节 + 改一行

### 4a〔改〕单品段最后一行

| | 原文 |
| --- | --- |
| 现在 | `本分支仅在matched_known_constraints且products非空时，使用products里的真实id输出[[PRODUCTS:商品ID1,商品ID2]]，最多4件。` |
| 改成 | `本分支在matched_known_constraints且products非空时，使用products里的真实id输出[[PRODUCTS:商品ID1,商品ID2]]；nearest非空时按【卡片规则·唯一版本】输出 nearest 的标记。两者合计最多4件。` |

（这一行后面还有「不要把sampleId、slug…」和「即使其他规则要求推荐2–4件…」，保持不动。）

### 4b〔加〕在单品段结束之后（也就是整段提示词的最后）追加两节

```
【收尾规则·唯一版本】（nearest 非空时按此顺序，一次说完，不重复）
1. 先用一句话说明“这次没有完全匹配”，不说成“没有这款”“店里没有”。
2. 逐件点名 nearest[i].product.name 和价格，把 nearest[i].violations 逐条说成顾客听得懂的话（超出多少钱、缺哪个风格、哪个场合不对、哪一点暂时核实不了）；不得把这些商品称为推荐或“可以接受”。
3. 给出两个出口：调整一个条件 / 先到这里。
4. 最后问一句是否需要转人工（演示）。
5. nearest 里某件 violations 为空，说明它已经是能核到的最近一件，措辞用“最接近”，不得暗示它满足了没法核实的条件。
nearest 为空（含澄清状态）：只说明本次限制，不点名任何商品。

【卡片规则·唯一版本】
- 工具返回 cardPolicy：mode=products 时，从 products 推荐并输出这些商品的标记；mode=name-once 时，正文点到的每一件 nearest 都要输出其标记（不得因为“不是推荐”省略）；mode=none 时不输出标记；mode=match-only 时只给本轮新候选的标记。
- 本节正文没有点名的商品，不要额外补标记。同一对话里前面已经给过卡片的同一件商品，本节不再重复输出标记，用“前面提到的这条”指代即可。
- 正文里没有商品名却输出了标记、或者正文点名了商品却没有标记，都算错误。
```
