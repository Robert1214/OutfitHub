## 4. 业务目标与已作出的取舍

我希望帮助有审美追求、热爱穿搭但不懂品类/风格/搭配/尺码的顾客。普通筛选能查商品，但新手可能不知道怎么搜，看到几套方案仍不会选。问题来源是我本人及朋友向店员求助的经历，不是已完成的大规模研究。

目前优先验证的价值：**帮助顾客理解不同搭配的差异，结合用途和偏好作取舍。** 提高下单率、减少转人工是目标，没有实测提升数字。

已确认原则：

- 预算、购买范围、明确排除品类与禁配关系不能擅自放宽。顾客不要鞋就不能用鞋补推荐；顾客只买一套，犹豫不等于同意都买。
- 已有主体与一起购买要区分；顾客只改预算时保留其他要求。
- 没有搜索结果、缺资料、没有已审搭配、确实超预算是不同情况，不能统称“全店没有”或默认转人工。
- 模型负责理解和解释，代码核对金额与约束；代码也可能因输入/实现错误失败，不能承诺万无一失。
- 当前面向顾客的成套推荐先使用店主认可组合；新组合可以先供内部集中评审。**不要求我在顾客咨询时随时在线审核。** 我已接受维护成本和覆盖有限的阶段性代价。
- 尚未确认不等于不适配。人工规则定义店铺口径，不代表客观唯一审美；不能把“高智感”等词简单等同几项标签就宣布理解到位。
- 差异解释要有资料依据；我的“舒适/清爽/温度更低时适合”等描述注明来源，不推导成分比例、保暖等级、防水、抗皱或合身保证。
- 我把“顾客已理解差异、还没决定或下单”判为部分成功。记录时区分理解、决策和成交，未下单不单独证明模型错误。
- “很多顾客都喜欢/都纠结”“已替你保存”“已经安排人工”等必须有事实或真实执行依据。当前助手没有保存搭配方案或真实人工审批队列；商品收藏入口/会话记忆不等于已执行保存。
- 我已经结束模型选型方法讨论。无需现在换模型、做泛泛模型排行榜或重新问我模型基础题。真实大小模型比较与费用结论仍未完成。
