## 1. 改了什么

### 1.1 D03-T2：把「拒绝调整」误判成转人工

根因两层：

1. **问题分类器**的「转人工」只写了「投诉、要求人工、连续无法解决」，「什么都不要改」被归进了转人工。
2. **直接回复 4** 文案固定为「已记录转人工请求」，顾客没提也会这么说。

| 位置 | 改动 |
| --- | --- |
| 问题分类器 instruction | 「转人工」限定为**顾客本人明确要求**；明确写入「拒绝调整条件、说算了/不买了/不要改、回答不用转人工」都归商品分类 |
| 直接回复 4 文案 | 「已记录转人工请求」→「已记录**你的**转人工请求（演示环境不会真的联系客服）」 |

### 1.2 S04：比较分支把内部样例当成顾客的商品

根因：`intent=comparison` 时工具**无条件**返回店主审核的固定比较组（海军蓝衬衫 / 米白运动外套 / 休闲西裤），模型据此当成顾客买的两件来比较。

| 位置 | 改动 |
| --- | --- |
| `src/lib/assistant-requirements.ts` | 新增可选字段 `compareItems: string[]`（≤6 条，每条 ≤60 字） |
| `src/app/api/assistant/products/route.ts` | 比较分支：`compareItems` 非空时返回 `status: compare_target_unavailable`，不返回商品/方案；为空时维持原固定组 |
| 同上 | 工具诊断日志加 `compare` 字段（只记条数，不记原话） |
| Dify 参数提取规则 13 | `compareItems` 只记录顾客指代对象的原话，不填店主资料商品名；只说「这两件」时至少记 `未指定` |
| Dify 代码节点 | `allowed` 白名单加入 `compareItems` |
| Dify 回答节点 | 比较段增加 `compare_target_unavailable` 分支：一句话说明只能比较店主已核对的固定组，不提任何商品/价格/材质/颜色，不输出标记 |

实测（工具直连）：

```
compareItems=["这两件"] → status=compare_target_unavailable, options=0
无 compareItems         → scope=internal_style_comparison, options=2（原固定组不变）
额外未知字段             → HTTP 400（严格模式仍生效）
```

### 1.3 S01/S02：鞋类给了通用穿搭建议而不是卡片

按用户决定**不给方向性建议，给商品卡片**。

| 位置 | 改动 |
| --- | --- |
| Dify 回答节点 `unsupported_request` 段 | 顾客要搭配鞋类时，若 `candidates` 非空，从 `candidates` 推荐在售鞋款（名称+价格），说明「这是单件鞋款推荐，不是整套搭配核对」；**不得给出无库存依据的款式清单**（短靴/切尔西靴/玛丽珍鞋等），不编造材质/保暖/防滑 |
