# 真实商品首测重试：limit改为4后通过

日期：2026-11-11。关联失败：[运行02](m5-catalog-run-20261111-02.md)。

用户反馈原文：“我把limit改成4，两题都通过了，你是怎么看出问题出在这的？”

## 结论与依据

本次HTTP 400的limit配置问题关闭。用户只报告将limit改为4即通过；结合旧实际DSL的limit=5、接口约定1至4，以及本地只改limit即可复现同样400的对照，确认旧limit与新接口范围不一致是此次阻断原因。并非需求提取错误或没有商品。

“两题通过”按用户确认记录，未回贴题目原文、HTTP字段或最终回复；不自行给两题分配用例编号，不补造逐字段证据，不将此扩大为全套评测、发布或项目UI通过。无需为了补记录重跑已通过题。

## 可复用判断过程

1. HTTP 400只说明请求未被接受，单看状态码无法定位limit。
2. 错误body定位到外层Params校验；此时尚未查询商品。
3. 对照接口约定，limit必须是1至4的整数，旧Dify配置曾为5。
4. 固定其余条件，本地limit=4返回200及359元裤子，limit=5返回同样400。额外q和重复键也能触发同一句错误，所以用户确认前不下唯一根因结论。
5. 用户只将limit改成4后实际预览通过，补齐修复有效的现场证据。

limit表示最多返回多少件候选商品，与顾客预算无关。当前报错把键名错误、数值范围错误和重复键合并成同一句，未直说limit超出范围，属于接口错误提示可改进项；本轮仅记录，不因已修复配置继续扩展代码或要求重测。
