## 2. 口径定义

### 2.1 每轮 token

```
每轮 token = usage.prompt_tokens + usage.completion_tokens
```

- 取 `results[].usage`（即 `done` 事件透传的 Dify `usage`），是 Dify 对整条工作流各 LLM 节点（意图/提取节点、回答节点等）的聚合值，不是单节点值。
- 若某轮 `usage` 为 `null` 或流未正常结束（无 `done`），该轮记为「无数据」，不按 0 计，并在表里单独标注。

### 2.2 每次「会话」token 与平均

```
每会话 token = 该会话所有轮（prompt_tokens + completion_tokens）之和
平均每会话 token = 全部有效轮 token 之和 / 12
```

- 12 会话按 `caseId` 分组（R01–R09、H01–H03），轮次 key 形如 `R01-T1`、`R01-T2`。
- 分母固定为 12；若某会话因无数据被排除，需同时报告实际参与分母的会话数，不得悄悄改分母。

### 2.3 单次成功任务成本

```
单次成功任务成本 = 总成本 / 通过会话数
总成本 = prompt_tokens 合计 × <DeepSeek 输入单价> / 1e6
       + completion_tokens 合计 × <DeepSeek 输出单价> / 1e6
```

- 单价口径：`<DeepSeek 输入单价>` / `<DeepSeek 输出单价>`（元/百万 token，以官方价目为准，待填）。
- 分母「通过」以本回归集的语义评审结论为准（技术检查通过不等于任务成功）；评审完成前写「待填」，不得用 17 轮全跑通冒充 12 会话全部成功。
- 若 `usage.total_price` 可用且非 0，优先直接使用（按会话累加），并与「token × 单价」交叉核对。
- 本地 Dify 的 `total_price = 0` 不代表零成本，**不得把 0 当作真实成本写入结论**；这种情况只报 token 量，成本列写「待算」。

### 2.4 登录/匿名与新会话对 prompt_tokens 的影响

- 回归脚本每个会话使用一个新的匿名 id（`eval-<uuid>`），不登录；同一会话内多轮复用 `conversationId`，续轮会把历史消息带入 prompt。
- 因此会话首轮 `prompt_tokens` 只含当轮输入 + 系统/工作流提示；续轮随历史累积。本次实测续轮 prompt 上升平缓（每轮约 +100~400），因为工作流上下文本身较大，历史占比小。
- 本次数据只代表「匿名、新会话」场景；登录态或跨会话长历史场景的成本不得直接套用。

### 3.1 单价与成本（2026-11-15 用户提供，DeepSeek v4 Flash）

用户提供的官方价目（元/百万 token）：

| 项目 | 空闲时段 | 高峰时段 |
| --- | --- | --- |
| 输入 · 缓存命中 | 0.02 | 0.04 |
| 输入 · 缓存未命中 | 1 | 2 |
| 输出 | 4 | 8 |

> 另有一档「2500 档」：输入缓存命中 0.15 / 0.30，未命中 4.5 / 9.0，输出 13.5 / 27.0（第二列）。本项目为演示流量，按表中第一档（并发 3，2500 档为更高并发）计算主口径，另一档作为上限参考。

**计费公式**

```
成本 = 输入 × 输入单价 / 1e6 + 输出 × 输出单价 / 1e6
单次成功任务成本 = 成本 ÷ 通过会话数(11)
```

**测算结果**（17 轮：输入 117,365、输出 18,701）

| 场景 | 17 轮合计 | 单次成功任务 | 单轮 |
| --- | --- | --- | --- |
| 空闲 · 缓存未命中 | 0.1922 元 | **0.0175 元** | 0.0113 元 |
| 空闲 · 缓存命中 | 0.0772 元 | 0.0070 元 | 0.0045 元 |
| 高峰 · 缓存未命中（保守口径） | 0.3843 元 | **0.0349 元** | 0.0226 元 |
| 高峰 · 缓存命中 | 0.1543 元 | 0.0140 元 | 0.0091 元 |
| 空闲 · 2500 档未命中 | 0.7806 元 | 0.0710 元 | 0.0459 元 |
| 高峰 · 2500 档未命中 | 1.5612 元 | 0.1419 元 | 0.0918 元 |

**结论口径**：单次成功任务成本约 **0.07~0.14 元**（空闲~高峰，缓存未命中、并发 2500 档），即 1 分钱到 1 毛五之间。报告里建议用「高峰 + 缓存未命中」= 0.0349 元作为保守数，或引用区间。

**置信说明**

- 回归脚本的每个会话使用新 anonId，续轮共享 conversationId，但 Dify 本地版未返回缓存命中字段；**本表默认按「缓存未命中」计**，因为更保守。
- 若线上启用提示词缓存（系统提示 + 工具定义基本不变），输入单价可降到 0.02~0.04，总成本约降为 1/5。

## 4. 局限

1. Dify 本地版 `total_price = 0` 且 `currency = USD`，只说明未配置模型计价；成本须用 token × 官方单价另算，且不要与 USD 字段混用。
2. 提取节点与回答节点是否都计入 `usage` 尚未核实；若存在不计价的节点，本表 token 可能偏低。
3. 回归脚本历史上 `usage` 一直为 `null`，本次起才有数据；此前运行的成本不可测。
4. 技术检查通过 ≠ 任务成功；「单次成功任务成本」的分母依赖语义评审。
5. 样本仅 12 会话、每会话 1–3 轮，为匿名新会话的评测题，不代表长期使用或生产流量的平均成本。
6. 同日稍早的 `runs/2026-11-14T13-50-25-338Z-732f3a3b` 因 Docker Desktop「unable to start」导致 Dify 超时，数据作废，不计入本表。
