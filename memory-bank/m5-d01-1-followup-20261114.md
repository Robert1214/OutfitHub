# D01-1 收尾 + 预算余额口径 + R04 判分（2026-11-14）

> 依据：用户 2026-11-14 拍板 `ai-pm-user-task-card.md` §8 D01-1（收尾选 C，并加转人工提示）与 D01-2（宽松判分）。本文件记录用户随后提出的三项修改。

## 用户原话（要点）

> R04成功；R02-T2应该给出商品卡片，不要只问提不提高；R01-T1应该说预算还剩xx元。改这三个，收尾。

## 三项改动

### 1. R01-T1：预算余额措辞（已改）

- 问题：首轮回「还剩约 ¥41」，H01-T1 回「还差 41 元额度」，同一事实两种说法，后者有歧义。
- 改法：工具在 `matched_known_constraints` 顶层新增 `budgetRemainderCents`（分，未提供预算为 null），`nextAction` 要求用「预算还剩XX元」句式，禁止改写成「还差/还欠」。
- 位置：`src/lib/assistant-catalog.ts`（单品分支）、`memory-bank/m5-catalog-answer-system.txt`（回答节点规则源）。
- 实测：`极简裤子 / 单件 400` → `budgetRemainderCents=4100`。

### 2. R02-T2：无匹配时给商品卡片（已改）

- 问题：旧行为只问「愿不愿意提高预算」，顾客拿不到任何可用信息，与 D01-1 选 C 不符。
- 改法（单品分支）：风格/关键词不匹配导致 `no_match_for_query` 时，回查同品类在售商品作为 `candidates`，`nextAction` 与 `priceBasisNote` 要求逐件标出违反了哪一条、给出「调整条件 / 先到这里」两个出口、最后询问是否转人工（演示），并输出卡片。
- 改法（搭配分支）：store 审核过的组合存在但金额/条件不符时，`no_match_for_query` 返回最接近的 `outfits` 与 `budgetAssessment`，规则同上。
- 位置：`src/lib/assistant-catalog.ts`、`src/lib/assistant-outfits.ts`、`src/app/api/assistant/products/route.ts`（`priceBasisNote` 注解）、`memory-bank/m5-catalog-answer-system.txt`、`memory-bank/m5-outfit-answer-rules.txt`。
- 实测：`摇滚风裤子 / 单件 400` → `candidates=[牛仔中长半身裙 299, 黑色高腰阔腿裤 359]`，`priceBasisNote` 已带 D01-1 约束。

### 3. R04：判为成功（用户改判）

- 原判：失败（只介绍一件裤子，未给搭配组合）。
- 用户改判：**成功**。
- 语义：顾客明确「只买裤子、已有衬衫」，助手推荐一条裤子并说明整体搭配感、不把已有衬衫计入金额，即为满足任务；**单品任务不要求输出多件组合**。
- 由此同步修正：`m5-cost-basis-20261114.md` §3.1 的通过数为 **11 / 12**（仅 R02 协商中）。
