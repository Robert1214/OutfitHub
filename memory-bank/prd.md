## 1. 背景与目标

### 1.1 背景

- 旧项目 `outfitexpert` 是一个「上传人像 + 单品图 → 试穿效果图」的单点工具，已完成 M1/M2，现已暂停。
- 本项目是一个**完整服装店 Demo**，用于作品集展示：从逛店、登录、购物车、下单、Mock 支付，到 AI 试穿、Dify 导购、后台管理，形成完整闭环。
- 只做到「收钱前一步」：不接真实支付、短信、物流，所有模拟环节必须显式标注。
- 目标不是做出可商用的店铺，而是**能演示、能讲清楚、能体现工程能力**。

### 1.2 目标

| 编号 | 目标 | 怎么算达成 |
| --- | --- | --- |
| G1 | 完整购物闭环 | 未登录可逛；登录后可加购、下单、演示支付、看订单 |
| G2 | AI 试穿进入购物流程 | 购物车勾选 1~4 件 → 用本人照片生成试穿图 → 可回看历史 |
| G3 | AI 导购可用 | Dify 聊天能推荐商品卡片、回答政策、转人工 |
| G4 | 后台可管理 | 管理员能增删改商品、查看/改订单、看看板 |
| G5 | 工程可讲 | 结构清晰、密钥安全、隐私有说明、边界有文档 |

### 1.3 非目标

- 不做真实交易、真实退款、发票、真实物流。
- 不做多商家、多店铺、复杂促销引擎、推荐算法。
- 不追求生产级高可用、压测、分布式、微服务。
- 不做多语言、国际化、复杂权限系统。

### 2.1 用户角色

## 5. 核心流程

### 5.1 购物流程（已定）

```
首页/列表/搜索
  → 商品详情 → 加入购物车（游客 localStorage / 登录 DB）
  → 购物车 → 勾选 → 去结算
  → 未登录？→ /login?next=/checkout → 登录后返回
  → 选择/新增地址 → 确认订单
  → 演示支付（二次确认）
  → 创建订单 + 标记商品售罄 + 清空已购购物车项
  → 支付成功页 → 订单详情
```

**异常分支**

| 情况 | 处理 |
| --- | --- |
| 商品已售罄 | 详情页按钮置灰「已售出」；购物车标灰不可勾选 |
| 结算时库存被买走 | 事务校验失败 → 提示「这件已被别人买走」→ 回购物车 |
| 未选地址 | 引导新增地址，不允许支付 |
| 未勾选商品 | 结算按钮禁用 |
| 重复点击支付 | 按钮 loading + 幂等键，防重复下单 |
| 支付页刷新 | 已创建订单则跳订单详情，不重复创建 |

### 5.2 AI 试穿流程（已定）

```
登录 → 个人中心上传本人照片（必须）+ 身材数据（选填）
  → 购物车勾选 1~4 件 → 点「AI 试穿」
  → /tryon 确认商品与照片 → 生成
  → 服务端：校验 → COS 中转 → 腾讯云 MPS（异步）
  → 轮询（约 60 秒，进度提示）
  → 结果图存入 COS 私有桶 → 写 tryon_records
  → 结果页：效果图 + 合身判断 + 保存 + 重新生成
  → 我的试穿可回看
```

**规则**

| 规则 | 说明 |
| --- | --- |
| 必须登录 | 游客不可试穿 |
| 必须有人像照片 | 没有则引导去个人中心上传 |
| 1~4 件 | 来自购物车勾选；超过 4 件提示先取消勾选 |
| 商品图来源 | 商品库 3 张图中的主图；不要求用户上传衣服图 |
| 图片与 MPS 标准 | 严格按 §6.8：原图上传不压缩，`tryon-1.0-lite` + 1K + identity，不改模型/分辨率/Prompt 结构 |
| 合身判断（上装/连衣裙/外套） | `refType=GARMENT` 且分类≠下装；用户身高 + 胸围、商品成衣胸围 + 版型齐全时生效：合身/偏紧/偏松 + 放量 + 建议方向；合身判断成立且商品衣长存在时附长度提示 |
| 合身判断（下装） | `refType=GARMENT` 且分类=下装；用户腰围 + 臀围、商品成衣腰围 + 臀围 + 版型齐全时生效：合身/偏紧/偏松 + 放量 + 建议方向；裤长/裙长仅展示，不自动判断 |
| 不判断品类 | `ACCESSORIES` / `SHOES` 不做合身判断；对应品类最低数据缺失只出图并标注「无尺码数据，请以实物为准」 |
| 不输出具体尺码 | 不出现「建议选 L 码」 |
| 额度 | 建议每账号每日 5 次，环境变量可调（待确认） |
| 结果保存 | 存 COS 私有桶，DB 存 key，签名 URL 访问 |
| 失败 | 友好文案 + 重试；不暴露 MPS 原始错误 |

> 下装放量区间为 Demo 建议值：腰围 紧身 0~2 / 合身 2~4 / 宽松 4~8cm；臀围 紧身 2~4 / 合身 4~8 / 宽松 8~12cm。M4 联调时可调整。

### 5.3 导购流程（已定）

```
进入 /assistant（或全站悬浮按钮）
  → 用户提问
  → Next.js /api/chat（服务端持 Dify Key）
  → Dify /v1/chat-messages（streaming）
  → Dify 问题分类：
      ├─ 推荐搭配 → 参数提取 → HTTP GET /api/assistant/products
      │            → LLM 组织回答 + [[PRODUCTS:id1,id2]]
      ├─ 活动/政策 → 知识库检索 → LLM 带引用回答
      ├─ 商品咨询 → 参数提取 → HTTP 查详情/库存 → LLM 回答
      ├─ 售后/投诉 → LLM 安抚 + HTTP 转人工
      └─ 其他 → Agent 节点（商品搜索/知识库/转人工）
  → 前端流式渲染；解析 [[PRODUCTS:...]] → 查库 → 商品卡片
  → 点卡片 → 商品详情；点转人工 → 记录 + 提示
```

**异常**

| 情况 | 处理 |
| --- | --- |
| Dify 未配置/Key 缺失 | 显示「导购助手暂未配置」，不报错 |
| Dify 超时/限流 | 友好提示 + 重试 |
| 返回商品 ID 不存在/已售罄 | 忽略或标「已售罄」 |
| 流式中断 | 保留已输出内容 + 重试按钮 |

## 6. 数据模型

### 6.1 设计原则

| 原则 | 说明 |
| --- | --- |
| 数据库 | Postgres；本地 Docker，部署 Neon 免费版 |
| ORM | Prisma |
| 金额 | 整数分（`priceCents`），避免浮点 |
| 时间 | UTC 存储，前端本地化 |
| 孤品 | 不做 SKU 表；颜色/尺码/成衣尺寸是商品属性 |
| 快照 | 订单项、地址、试穿项存快照，商品改价不影响历史订单 |
| 图片 | 商品图存本地 `public/products/`；用户照片/试穿结果存 COS 私有桶，DB 存 key |
| 删除 | 商品软下架（status）；订单不物理删除；用户照片可删并删 COS |

### 6.2 实体关系

```
User 1─N Address
User 1─N Order 1─N OrderItem
User 1─1 Cart 1─N CartItem
Category 1─N Product 1─N ProductImage
User 1─N TryonRecord 1─N TryonRecordItem
User 1─N ChatSession 1─N ChatMessage（可选）
```

### 6.4 核心表字段

**products（商品）**

| 字段 | 类型 | 必填 | 说明 |

| categoryId | String | 是 | 分类 |

### 6.6 库存与并发（已定）

- 加购不锁库存；下单时用事务校验 `status=ON_SALE` 且 `stock=1`。
- 更新用条件更新：`updateMany({ where: { id, status: 'ON_SALE' }, data: { status: 'SOLD', stock: 0 } })`，`count=0` 表示被买走。
- 订单创建与商品售罄在同一事务；失败则回滚。
- 取消/退款：后台手动恢复 `ON_SALE`、`stock=1`（演示）。

### 6.8 试穿图片与 MPS 标准（沿用旧项目，已定）

> 旧项目已实测调优；M4 接入时必须按此执行，不得再自行压缩、改模型或改分辨率。

| 项 | 标准 |
| --- | --- |
| 人像照片 | 1 张；JPG / PNG / WebP；≤8MB；≥200×200；全身 / 半身 / 大头均可，不拦截非全身 |
| 单品图 | 1~4 张；JPG / PNG / WebP；≤8MB；≥200×200；干净商品图；配饰图不要带模特脸/手；不要求固定比例 |
| 上传链路 | 原图上传，不压缩、不重编码；900px / quality 0.85 仅用于浏览器预览与 localStorage，**不得作为 MPS 输入** |
| 单品类型 | `garment` 衣服 / `accessories` 配饰 / `shoes` 鞋；眼镜、帽子、项链必须 `accessories`，Prompt 用「佩戴」 |
| MPS 模型 | `tryon-1.0-lite` |
| 输出分辨率 | `1K`；不用 2K（只放大画布，多耗约 20 秒，无额外细节） |
| 参考图组合 | `garment` / `accessories` / `shoes` × 1~4 + `identity`；`identity` 用同一张人像，固定追加在最后 |
| Prompt | 按类型生成「替换服装 / 佩戴配饰 / 替换鞋」；统一追加「严格保持五官、脸型、肤色、发型不变，不要重新生成面部；保持姿态、背景、光照不变」 |
| 结果 | 1K 效果图；新项目存 COS 私有桶，DB 存 key；旧项目用 MPS RMS 链接，本项目改为私有存储 |

> 旧项目实测结论：900px 压缩输入会导致五官变形；原图 + `identity` + Prompt 后约 85% 可用。2K 输出不增加细节。配饰参考图带脸/手时，模型可能把脸/手画进结果。

## 8. 非功能需求

### 8.1 隐私（已定）

| 数据 | 敏感性 | 规则 |
| --- | --- | --- |
| 身材数据（身高/体重/三围） | 高 | 明示用途、仅本人可见、接口不返回给他人、可清空 |
| 本人照片 | 高 | COS 私有桶、短时签名 URL、仅试穿用途、不用于训练、可删除 |
| 试穿结果 | 高 | 私有桶、仅本人/管理员可见、可删除 |
| 订单/地址 | 中 | 仅本人/管理员可见 |
| 聊天记录 | 中 | 仅本人/管理员可见（如落库） |

- `/privacy` 页面写明：收集什么、为什么、存哪、多久、怎么删。
- 注册页有《用户协议》《隐私政策》链接。
- 不把照片/身材写入日志；错误日志不含签名 URL。
- Demo 数据可由管理员清理；用户删除即时删 COS 对象。

### 8.2 安全（已定）

- 密钥只在服务端 `.env.local` / 部署环境变量；`.env.local` 不入库；提供 `.env.example`。
- 前端源码不得出现腾讯云 AK/SK、Dify Key、数据库密码。
- 密码 bcrypt（cost ≥10）；验证码固定仅演示，页面明示。
- 会话 HttpOnly + Secure + SameSite=Lax；JWT 7 天。
- 所有受保护 API 校验会话；后台校验 `role=ADMIN`。
- 越权：订单/试穿/地址查询强制 `userId = session.user.id`。
- 上传：类型白名单、≤8MB、服务端解码校验、文件名随机化。
- 搜索：Prisma 参数化；LIKE 通配符转义。
- 限流：登录 5 次/分钟；试穿按额度；聊天 20 次/分钟（内存即可）。
- 错误：用户只看到友好文案；原始错误只进服务端日志。

| 指标 | 目标 |
| --- | --- |
