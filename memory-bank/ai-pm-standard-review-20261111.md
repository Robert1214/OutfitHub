# 对照在职AI产品经理建议：当前证据与缺口

日期：2026-11-11。来源：用户粘贴的求职项目建议，询问当前是否按此标准推进。以下为基于项目本地证据的评审，不把建议中的指标阈值或路线变更自动视为用户决定。

## 总体判断

方向一致但证据尚不完整。最充分的是产品边界、具体规则、分层失败定位和修复回归；较薄弱的是非AI基线比较、模型选型实测、同版本整体效果/稳定性、成本延迟分解与真实用户价值验证。Ownership文档§4.2–4.8已涵盖相关标准，存在文档不代表已具备全部能力证据。

| 三层逻辑 | 已有 | 尚缺 |
| --- | --- | --- |
| 业务背景与AI必要性 | 用户本人及朋友的穿搭困难、店员凭经验挑选的当前办法；预算内推荐、符合店主审美、商品事实准确的目标 | 用户任务观察；与搜索/筛选/规则方案完成同类任务的对比；尚无转化提升或减少人工的实测证据 |
| 方案设计与评估 | LLM理解/表述，工具查事实/算预算，店主确认搭配；Chatflow可追踪；边界/多轮/无匹配用例 | 大小模型与纯规则的公平对比、冻结版本整体评测、未参与调优的保留题、指标分母和正式验收门槛 |
| 问题定位与闭环 | 参数遗漏/预算包含关系错误、页面来源混淆、配置未同步、limit范围400等复盘；有原始失败和重测 | 同一最终版本批量复验、未见问法的稳定性、修复对任务完成率和耗时的量化改善 |

## 已能诚实讲述的判断

- 商品价格/库存从数据库读取、预算用代码计算、未知组合待核实，属于通过产品与工具约束降低幻觉；不能声称消除了幻觉。
- 是否需要澄清由缺项/冲突决定，接受必要多轮；“预算包含上衣”提取为null引发重复确认，与HTTP limit不合法是不同故障。
- 固定样例无条件作为currentProduct导致伪称页面商品，修复信息来源与工具载荷；仅要求模型更谨慎不解决工具给错来源。
- limit=4与5单变量对照、用户实际改值恢复构成配置故障闭环；这是集成能力例子，不能作为模型效果优化的唯一案例。
- 已有三节点编排能覆盖限定任务，当前不必为了作品集引入Agent；若未来出现动态规划需求，应以同任务完成率、耗时、成本决定，而非声称Agent永远不适用。
- 指定真实衬衫与裤子仅有一条已确认组合，是有限规则能力和总价/流程验证，不代表学会店主审美或可泛化搭配。新搭配31项本地通过，Dify新配置仍待用户验收。

## 指标与证据不能混用

- 31项为15样例＋8单品＋8搭配的代码/接口回归，不是31条模型任务准确率，也不是线上业务收益。
- 历史m5-eval-results.csv有49行，7行behavior_ok非空，22行有expected_products。未自动评分的42行不是失败也不是通过；需人工判分或有意义的检查补证。旧CSV与当前商品/规则/Prompt版本也不能直接合并比较。
- 近期网站API三轮总耗时约6.7–8.6秒，首段约6.3–8.2秒，仅是三个观测，不据此声称P95达标或判定基模慢。
- 两件合计正确、ID合法和推荐确实有用是不同维度；保守阻断可能降低幻觉，但也可能漏掉可行组合、反复澄清或未解决需求。

建议下一份评估至少报告任务完成率、硬约束违反率、必要/多余澄清、应有候选召回、无依据商品事实、首段/总耗时及每个成功任务的成本。每项明确分母、支持范围与未评部分。数值门槛仍需结合基线和业务容忍度由用户确定，不在本评审擅自设置。

召回例子：人工核对某问题共有5件合格候选，系统推荐3件，其中2件合格，则推荐精确率为2/3，候选召回率为2/5。适用前提是答案集合确已标注；未知审美组合不当负例，不因高精确率掩盖低覆盖率。商品召回和政策文档召回应分开评价。

## 需要补的实验

1. 同版本评测基线：固定应用配置、代码、商品数据、模型参数和用例；分开发调优题与保留验证题。将本轮失败纳入回归，避免调到一题成功就宣称整体稳定。
2. 最小方案对照：在相同任务和工具上比较规则/筛选基线、成本较低模型与当前模型，考察语义变体、多轮、否定条件、成本与延迟。不能把“传统规则/小模型不行”当未经验证的前提。模型参数规模不透明时也不猜测型号大小。
3. 真实任务观察：邀请少量目标用户知情参与，比较页面筛选和助手的相近任务、记录完成情况/时间/困惑/接受理由；小样本用于发现问题，不外推转化率。无足够真实流量时先做离线对照，不虚构线上A/B。
4. 性能分解：分别查分类、提取、工具/数据库、生成与网络耗时及重试；归因后决定是否合并节点、更换模型或改检索。成本包含多轮、重试、模型及其他收费调用，不能只比单次token单价。
5. 政策检索专题按实际问题再做：商品事实继续走结构化工具。当前文档记录500 tokens/重叠50/topK3等只是配置，未证明最优。先检查答案是否存在、正确片段是否召回、召回内容是否支持最终回答，再分别对照切分/检索/生成；不为展示RAG而把商品塞入向量库。

## 协作方式的调整建议

当前带练较多落在节点复制、字段检查、用例重试；工程工作必要，但不能以此替代用户的产品判断。完成已授权搭配小块后，建议优先补当前范围的冻结评估和方案决策记录，再继续扩功能。此为建议，不视为用户取消当前Dify待验步骤或批准新模型/线上实验。

每个小块由用户尝试回答：问题是什么、有哪些替代方案、选当前方案的依据与代价、什么证据会让自己改选。AI辅助整理与实现，用户应能用自己的话解释，并明确哪些判断是自己作出的。
