# 测试数据事故记录（2026-11-17 ~ 2026-11-18）

记录误删用户数据的三次经过、原因与改进，避免重犯。

## 事故 1：删掉整个 COS `wardrobe/` 目录（2026-11-17）

**经过**：第 6 步完成后清理测试数据，脚本删除的是 `wardrobe/` 前缀下所有对象。

**影响**：用户上传的红色鞋子图片被删（数据库记录还在，图片 404）。

**原因**：清理脚本按「目录前缀」删，不是按 `wardrobe/{userId}/`。

## 事故 2：`delete from wardrobe_items;` 未带条件（2026-11-17）

**经过**：修复「表单残留」bug 时清空衣橱，执行了无 `where` 的 delete。

**影响**：用户的红衬衫等单品被删。

**原因**：SQL 图省事，没写 `where "userId" = ...`。

## 事故 3：第 13 步联调（2026-11-18）

**经过**：
1. 先跑 `dev:clean`（只清 demo，正确）
2. 发现「用户账号」下还有 7 件单品、1 套搭配、3 次试穿（此前遗留）
3. 为了从零开始测试，执行了**不带 where** 的：
   ```sql
   delete from tryon_records;
   delete from outfits;
   delete from wardrobe_items;
   delete from tags;
   ```
4. COS 也清了整个 `wardrobe/`（61 个对象）
5. 随后**用用户账号 `12345678910`** 登录跑完整流程（应该用 demo）

**影响**：用户衣橱被清空，之后衣橱里是测试用的 Polo 衬衫、adidas 外套等。

**原因**：
- 守则写的是「只用 demo 账号」，但执行时用了用户账号（问题 5）
- 清理时图快，手写 SQL 没带 where（问题 3）
- 脚本 `clean` 本可避免，但没用上


```

    单品 3 | 搭配 1 | 试穿 2 | 标签 2
【用户账号·勿动】 用户8910 / 12345678910
    单品 5 | 搭配 2 | 试穿 1 | 标签 3
```

测试前后各跑一次，能立刻发现是否误写/误删。

### 3. 自动化测试脚本固定 demo 账号

浏览器测试统一登录 `demo@outfitexpert.demo`（邮箱+密码），不再用手机号账号。

## 当前应遵守的最短流程

```bash
# 1. 测试前：看清两个账号各有多少数据
npm run dev:whoami

# 2. 清理（只清 demo）
npm run dev:clean

# 3. 造数据（demo 账号）
npm run dev:seed

# 4. 跑测试（登录 demo）

# 5. 测试后：确认用户账号数据没变
npm run dev:whoami
```

**如果用户账号数据在步骤 1 和步骤 5 之间变化了，说明测试写错了账号。**
